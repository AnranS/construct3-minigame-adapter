// Construct project script
const bridge = runtime.objects
  .MiniGameBridge.getFirstInstance();

await bridge.init();

if (bridge.supportsAPI("showToast")) {
  try {
    await bridge.callAPI("showToast", {
      title: "Your mini-game is ready", icon: "none"
    });
  } catch (error) {
    console.error(error.code, error.message);
  }
}

More common questions →
Does installing the addon add a mini-game export option?

Not currently. MiniGameBridge exposes platform calls inside Construct. Export HTML5 first, then use the separate CLI to convert it into a native WeChat, Douyin, or TikTok mini-game project.

Can it run any H5 game or third-party JavaScript SDK?

That is not guaranteed. Mini-games do not provide a complete browser, and this project implements only the required DOM, storage, networking, and audio compatibility. SDKs that rely on page layout, remote scripts, or a full browser environment need individual adaptation.

Has every API in the catalog been tested on a real device?

No. The catalog currently has {{API_COUNT}} unique names: {{WECHAT_COUNT}} for WeChat, {{DOUYIN_COUNT}} for Douyin, and {{TIKTOK_COUNT}} for TikTok. The historical WeChat IDE baseline had 133 / 171 methods available and 17 self-checks passing. Those results do not verify newly added APIs or TikTok.

Can I fulfill an order directly after a TikTok payment callback?

No. The client callback only ends the payment-panel flow. Your server must verify the webhook, check the order, and fulfill it idempotently. The game queries your backend for the final status. Read the IAP integration guide →

Does the public repository include the Construct engine?

The repository provides adapter source, the addon, and .c3p examples. Export HTML5 with your own Construct editor, then run the converter. Applicable terms for the Construct engine and SDK belong to their respective rights holders.
